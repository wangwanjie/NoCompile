## NoCompile 0.2.2

### 新增

- **断开工程**：控制台顶栏、菜单栏与「文件」菜单可断开当前工程（停止监听并断开已连接的 App），断开后可一键重新打开最近的工程
- **导出诊断包**：控制台日志栏的 📦 按钮或菜单「导出诊断包…」生成 zip，包含各环节诊断日志、编译失败的完整命令与输出、主线程卡顿时自动采集的调用栈、引擎状态与最近注入记录，便于反馈问题
- **客户端版本校验**：App 内的客户端与 Mac 端版本不一致（例如 App 包里拷贝的仍是旧 bundle）时，控制台、系统通知与 App 浮层提示重新编译 App，并暂停向其推送热重载

### 优化

- 大型工程的构建日志改为流式解析并增量合并：1.1GB 的日志从 217 秒 / 4.5GB 内存降到约 8 秒 / 不到 100MB，修复打开大型工程后 Mac 端长时间无响应、转菊花
- 头文件改动改用依赖索引查找引用方，被大量文件引用的公共头文件只重编同名实现文件
- 本地 Pod / 子模块 git 拉取、合并后能正确触发热重载：一次 git 操作合并为一批处理，并监听 Podfile.lock 中工程目录之外的本地 Pod
- App 内状态浮层支持多行，长提示不再被截断

### 修复

- 存在同名工程（如两份 kugou.xcworkspace）时可能用错另一份工程的构建日志
- 切换工程、重启监听时可能卡住主线程
- 日志达到上限后「跟随最新」失效

> 升级后请重新编译运行接入了 NoCompile 的 App，CocoaPods / SPM / Carthage 接入的请同时把依赖更新到 0.2.2。

详见 [接入指南](https://github.com/wangwanjie/NoCompile/blob/main/Docs/Integration.md)。
