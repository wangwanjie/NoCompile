## NoCompile 0.2.13

### 修复

- **pod install / update 后控制台一直刷头文件分析，只能重启 NoCompile 才恢复**：依赖工具一次改写成千上万个文件时，引擎逐个分析每个头文件，期间打开的文件描述符没有及时释放，最终耗尽进程上限（默认 256）。之后重新打开工程时读不到目录、文件基线为空，被碰到的每个文件都被当成新增文件。现在：
  - 一批改动超过 100 个文件时，在分析头文件之前就跳过并提示重新编译，不再堵住引擎
  - 子进程调用不再滞留描述符，启动时把打开文件数上限提高到 10240
  - 扫描工程目录失败时不再建立空基线，会自动重试
  - 读不到工程目录时按实际原因提示，描述符耗尽时不再误导去开隐私授权
- **依赖工具原样重写的文件被当成改动**：pod install / update、git checkout 等会把内容没变的文件重新写一遍。现在文件基线会记录内容摘要，内容没变的文件不再触发热重载。摘要缓存在 `~/Library/Caches/NoCompile/FileDigests`，再次启动时直接复用；首次启动在后台计算，十万个文件约 1 秒
- 菜单栏图标在引擎未启动时显示为黑色的问题

### 升级提示

- 升级后无需改动工程，已编译的 App 仍可正常热重载
